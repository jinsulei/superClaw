# Capability Registry

This registry is not a claim that every capability is fully implemented. It records current evidence and the target adapter boundary. Reserved or planned capabilities must not be treated as production-ready.

Capability ownership follows the Hermes 1.0.7 layer order: Layer 3 owns task judgment, Layer 4 owns agent/tool/model/platform adapters, Layer 5 owns observability, Layer 6 owns business modules, and Layer 7 only presents state. All rows preserve `current_state`, `target_state`, `evidence_path`, `missing_contract`, `migration_rule`, `risk_level`, and `no_parallel_impl` where an existing capability is involved.
